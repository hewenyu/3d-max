# Modifier Evaluation Contracts

All modifier parameters are validated by `meshModifierSchema`; the retained base is editable. `evaluateModifiers` returns evaluated geometry and never mutates the supplied base or stack. The optional `ModifierEvaluationContext` supplies a stable target object ID and an operand resolver returning evaluated mesh plus the operand-to-target matrix.

`referencedOperandIds` includes disabled Boolean modifiers. `validateModifierDependencies` rejects missing references and cycles before evaluation, including disabled references. `createModifierEvaluator(project, sourceMesh)` validates the requested dependency closure and memoizes evaluated operands for one immutable project snapshot. Create a new evaluator for every changed project or dependency version; do not reuse it across mutations. The source callback converts only the retained base or primitive, never the full stack.

Referenced Boolean operations use base object and parent transforms. Object keyframe motion does not alter a Boolean shape: animate the resulting model as an object after modeling. Hidden and locked operands remain readable inputs; this evaluator does not move or modify them. Bone attachments, actor/vehicle/effect rigs and missing parents are unsupported and fail explicitly. The command integration is responsible for propagating locks on dependent results when an operand edit would change a locked object, preserving references across duplicate/template operations, and guarding the project revision at commit.

`meshBoolean(target, operand, operandToTarget, operation)` is the shared geometry primitive for destructive and retained Boolean commands. It accepts consistently oriented closed solids, including geometrically matching split subedges produced by CSG. It preserves the existing 30000-triangle limit per operand, rejects singular/non-finite relative transforms, and checks its result. Empty results fail because the editable mesh schema requires at least one nondegenerate face. Evaluation uses `three-bvh-csg` constrained clipping, not a second custom CSG kernel.

Boolean output additionally searches the 27 neighboring spatial cells at the existing 0.000001-meter conversion tolerance. This joins near vertices missed by quantization buckets without moving the retained representative or deleting faces. A transitive group requiring a vertex displacement beyond the tolerance, or welding that collapses/reverses a face, fails with `MODELING_PRECISION`. This is not a general remesher: matching geometric subedges with an actual T-junction can still have separate index boundaries. Inspection reports those boundaries honestly; source topology and explicit bake/edit behavior are not relabeled as manifold merely because the CSG surface-solid check passes.

The current bevel modifier delegates to `topology/bevel.ts` and affects every non-coplanar edge. It accepts a globally convex, closed, outward-oriented shell with simple planar faces. Width is in local meters; segments are 1..16; shape runs from flat chamfer (0) to circular (1). The topology kernel limits total profile planes to 256 and rejects overlapping or consumed original faces. Concave meshes and open shells receive the kernel's structured diagnostic. These input boundaries apply to both the modifier and the topology command.

Dependency evaluation limits are 32 levels and 256 objects per requested closure. These are explicit guards, not a measured performance guarantee. Measured complexity and interaction results are recorded separately in [advanced-modeling-performance.md](../../docs/advanced-modeling-performance.md).
