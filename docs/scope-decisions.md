## 决定与边界

| 编号       | 决定                                                                   | 对当前交付的影响                                                                                       |
| ---------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| SD01 / H07 | 雕刻、复杂拓扑、专业材质、布料、毛发、流体等专业扩展暂时不需要。       | H07 已由用户解决，本次交付不要求新增这些专业系统。“暂时不需要”不等于已实现，也不等于永久取消。         |
| SD02 / H08 | 不需要内置聊天助手和外部生成式 3D 服务，使用外部 Agent 通过 MCP 交互。 | H08 已由用户解决。自然语言理解、规划和调用由外部 Agent 提供；软件提供真实 MCP 能力、状态、预览与产物。 |
| SD03       | 所有 Web 可用能力都必须通过 MCP 实现。                                 | 这是强化验收要求。必须逐项证明 Web 与 MCP 的能力等价，不能以已有工具数量或调用成功数量代替。           |

现有基础网格编辑、挤出、布尔、曲线、地形、修改器、模板、角色 IK、接触约束、必要的物理辅助、表情与口型等能力继续保留并接受验证。专业扩展的范围决定不削减这些基础能力，也不改变四类视频、可编辑项目、持久化、预览、导出及工程规范的验收要求。

用户关于“参考图”的表述是在说明其创作方式，并非新增参考图工具或参考图生成流程的产品需求。本次决定没有要求集成下游 AI 视频生成，产品流程仍截止白模视频导出。

## Web 与 MCP 等价验收

验收从实际 Web 能力出发，逐项映射到 MCP，覆盖项目与文件、建模布景、角色表演、时间与摄影机、剪辑审片、资产与历史、预览播放以及导出任务和产物。观察、选择、播放等客户端能力也需要明确可通过 MCP 达到的等价结果与反馈，不能默认为“仅界面功能”而跳过。

每项映射至少记录以下证据：

| 验收字段       | 要求                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------- |
| Web 能力与入口 | 具体用户动作、输入、状态及预期结果，包括错误和边界情况。                                            |
| MCP 等价入口   | 可被外部 Agent 实际发现并调用的工具或协议资源，附参数与结果定义。                                   |
| 一致的业务语义 | UI 与 MCP 共享领域操作、项目状态、校验、权限、锁定和历史；涉及编辑时覆盖版本冲突、幂等与原子性。    |
| 实际效果       | 读取与反馈反映真实状态；编辑能在 Web 中观察并继续操作；预览来自真实渲染；视频与文件产物可实际取得。 |
| 同等适用范围   | Web 支持的文件大小、内容类型、项目规模及任务状态具有可用的 MCP 路径，并用对应实际输入验证。         |
| 完成依据       | 对应实现、行为断言、实际调用或跨入口验证记录，以及明确的代码版本与残留差距。                        |

[151 个工具的历史调用记录](../.data/full-delivery/final-candidate-04/checks/mcp-coverage.json) 证明已注册工具具有成功的独立调用。它不证明 Web 能力清单已经完整映射，也不证明全部行为、文件规模或状态均等价。现有测试和四片实战证据可以复用，但缺少映射或实际等价结果的能力仍需补齐验证。

例如，[四片项目包的历史恢复记录](four-films.md#portable-projects-and-reopening) 中，赛车包为 50,292,001 字节，太空包为 256,528,195 字节，两者通过 HTTP multipart 导入。历史 `project_package_import` 的 32 MiB base64 输入限制要求更大包使用浏览器上传。这些历史记录不能单独证明同等规模的 MCP 导入。新加入的 MCP 分块传输已通过 [四包实测](../.data/full-delivery/final-candidate-09/mcp-package-checks-complete/suite-report.json)：335 个分块、257 个原始历史快照、实际修改与撤销、代表镜头再导出及真实进程重启均通过，闭合此项规模差距。其他能力按 [Web/MCP 等价映射](web-mcp-parity.md) 和 [完整验收矩阵](full-delivery-matrix.md) 分别验证。
