## 失败原因与修正

1. 生产构建把 WASM 改名为 `opensubdiv-CMrjEhWb.wasm`，旧测试仅匹配 `opensubdiv.wasm`。现从 BrowserContext 收集包含 Worker 的实际响应，验证 HTTP 200、163131 字节、WASM 头 `0061736d01000000`，二进制 SHA-256 为 `28ac706cb6afd7517b4bda15660724b91838ad108a91aca7b9e988b44c08ec20`，并记录实际 `GeometryWorker-CnBFSVyE.js`。五类修改器的参数、源保留和启停像素变化断言保留。
2. 受控复选框在异步建模提交后才改变 DOM，`uncheck()` 的立即检查早于该提交。测试改为真实 click，再等待 MCP 数据中 `enabled:false` 和页面未勾选状态。
3. 曲面创建已经改为异步任务，但旧 `expect.poll` 回调中的源类型断言在任务排队时直接抛出。现重试完整断言，仍要求持久化源确实成为指定曲面。
4. 网格重新准备会卸载旧诊断面板，旧报告被清空，不能断言一定保留“诊断待刷新”文字。现验证旧边界选择不可用，重新运行 Web 诊断，要求“封闭、法线一致、1 个连通体”、边界数 0，再以带版本和上下文 guards 的 MCP `mesh_inspect` 独立确认边界数为 0。
