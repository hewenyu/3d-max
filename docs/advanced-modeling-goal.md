# 高级 3D 建模交付目标

创建日期：2026-09-08。

用户要求：

> 下一个目标是高级3d建模能力，你创建一下目标

## 目标与边界

在现有白场 Whiteframe 项目上完整交付高级几何建模能力，让用户和外部 Agent 可以制作、检查、修改和复用复杂白模资产，并直接用于现有表演、镜头、剪辑和视频导出流程。不能以只有界面、工具注册、基础几何拼接或短演示作为完成标准。

本目标将网格拓扑与高级几何编辑作为新的必做范围，扩展上一目标中的基础建模能力。其余沿用用户此前的范围决定：雕刻、专业材质节点、布料、毛发、流体及额外复杂动力学暂不纳入；不内置聊天，不接入外部生成式 3D 服务或下游 AI 视频生成。自然语言理解与规划由外部 Agent 提供，所有 Web 可用能力必须提供真实 MCP 等价入口。

原始完整目标、历史范围决定、四片验收和已交付版本记录保持不变；本文件描述新增目标，不改写历史完成状态。

## 实施与功能验收

1. 先审查现有网格、曲线、地形、修改器、导入、选择和持久化代码，建立高级建模逐项验收矩阵。记录现状、新增能力、Web 入口、MCP 工具、边界、验证方式及状态；已有顶点/面编辑、挤出、CSG、镜像、阵列和 Loop 细分不能重复计为新增高级能力。先固定具体行为与复杂度限制，不通过删项或降低标准迁就实现。
2. 建立适合拓扑编辑的数据模型与稳定元素标识，支持顶点、边、多边形面及邻接查询，正确处理边界、面朝向和渲染三角化。提供旧网格、SQLite 项目、历史快照、模板和项目包的兼容或显式迁移；拓扑变化后的失效选择与引用必须明确更新或报错。
3. 完成组件级编辑工作流：顶点/边/面模式、实际视口拾取、框选与套索、可见面或穿透选择、增减选、反选、关联选择、边环和边带、选择扩展/收缩。支持数值输入及变换工具，提供世界/局部/法线方向、合适的枢轴、吸附和比例编辑。Web 和 MCP 均能读取、定位及修改真实选中元素。
4. 完成高级拓扑操作：区域及独立面挤出、内插、可调段数倒角、环切与滑移、切割/平面剖切、桥接边环、补洞、合并与按距离焊接、拆分、溶解、删除和法线修复。明确定义开放边界、孔洞、非流形、退化面及不兼容输入的行为；不支持的输入原子失败，不留下损坏网格。
5. 扩展非破坏建模：可继续编辑的布尔操作及操作数引用、倒角、实体化、带焊接的镜像、曲线阵列、弯曲/扭转变形和适合多边形控制网格的细分。修改器支持参数修改、排序、启停、复制和显式烘焙，清楚表达依赖与修改影响。编辑笼、求值结果、预览、碰撞辅助和导出必须使用一致的几何求值语义。
6. 完成曲线与曲面造型：可编辑曲线控制点及切线、闭合曲线、自定义截面扫掠、旋转成型和多截面放样；支持分段精度、封口及厚度。曲线源和参数可持续编辑，生成网格可显式转换为拓扑编辑对象。处理路径方向、拐点、自交及不兼容截面，提供明确诊断。本目标不以完整 CAD/NURBS 内核为验收前提。
7. 完成建模检查和资产流转：线框/实体显示、法线与边界显示、元素数量、尺寸及几何合法性检查，定位重复元素、退化面和非流形位置，并提供对应修复操作。允许显式转换兼容的导入静态 GLB/glTF 网格继续编辑；不兼容骨架、动画或其他属性需保留原资产并说明转换边界。可导出所选对象或场景的实际 GLB，并通过项目包保留源拓扑、修改器、依赖资产与历史。
8. 全部新增能力通过正式 MCP 暴露，包括组件查询/选择、拓扑编辑、修改器、曲面参数、几何诊断、实际图片和模型文件。Web/MCP 共用领域命令、状态、校验、权限、锁定和历史，支持原子批量、幂等、版本冲突和结构化错误。耗时操作应有真实进度和可取消行为；无浏览器时仍能完成建模、检查、渲染预览及取得产物。
9. 保持交互可用性：复杂计算隔离于界面主线程，控制求值缓存和内存，输入超过明确限制时给出可理解的错误。使用不同复杂度的真实网格测量选取、编辑、修改器重算、撤销、保存及预览耗时和内存，并记录机器条件、限制与测量结果；不以静默降精度、冻结界面或仅低复杂度演示代替验收。

## 实际作品验收

制作至少四个不同建模类型的复杂白模资产或场景：车辆车体、飞行器或机械装置、带拱洞/楼梯/栏杆的建筑地标，以及依靠扫掠/旋转/放样制作的曲面道具。

- 四个作品必须展示真实细节与结构，覆盖硬表面、孔洞与厚度、拓扑调整、修改器依赖及曲面造型；提前为每个作品建立可检查的建模清单。
- 使用正式 Web/MCP 通用功能制作并保留操作记录；至少一个作品由外部 Agent 通过公开 MCP 从空项目完成建模、检查、修正和导出。不能以导入现成成品、演示专用代码或独立渲染器代替产品能力。
- 每个作品交付可重新打开和继续编辑的项目包、实际 GLB、多角度图片和由正式视频导出功能生成的展示视频。展示应能看清轮廓、曲面、倒角、孔洞和关键拓扑效果；视频至少 720p、24 fps，并实际核验编码、帧数和持续运动。
- 对每个作品实际执行修改参数或拓扑、撤销/重做、保存、服务重启、项目恢复及再次导出；比较真实几何与渲染结果，检查资产、历史和依赖完整性。
- 不把上一目标已通过的四部两分钟影片重复计为新作品；保留其有效验收。新实现必须验证它们的项目兼容、播放及受影响的预览/导出行为，按实际变更范围补充回归。

## 工程与完成标准

- 业务数据使用 SQLite，二进制由数据库引用文件系统；迁移、备份、导入和恢复须保持一致性。
- 按拓扑内核、建模命令、几何求值、渲染、交互、持久化、HTTP/MCP 和导出拆分模块，避免巨型组件、循环依赖与重复业务逻辑。每个源码文件不超过 1000 行，构建自动检查，禁止压缩排版规避。
- 保持统一格式、严格 TypeScript、边界输入校验和结构化错误。复用合适的成熟几何算法及库，验证许可与数值行为；必要的自定义实现必须有清楚的数据约定和针对退化输入的测试。
- 完成与风险匹配的几何、拓扑、迁移、SQLite、Web/MCP、撤销恢复及导出测试；用真实浏览器验证桌面/手机布局、3D 非空像素、选中反馈、人工与 MCP 双向操作及实际图片/视频/模型导出。
- 完成全部新增验收矩阵、四个实际作品、兼容回归、格式/结构/类型/构建及必要测试；提供运行地址、MCP 使用文档、作品入口、验收报告和代码版本，验收通过后 commit 并推送。
- 允许分阶段实施和提交，但持续推进到本目标全部适用项通过。只有完整交付和验证完成才标记目标 complete；如遇实际未解决问题，保留失败证据并如实记录，不宣称完成。
