# Web 3D 白模预演工具：产品需求讨论稿

- 版本：0.4
- 日期：2026-09-07
- 状态：首版产品基线；已补充导演工作流、白模视频导出边界及用户明确的工程约束。实现与验收进度见 `implementation-plan.md`。

## 1. 产品定位

一个运行在浏览器中的 3D 白模预演与镜头制作工具。用户可以在可视化编辑器中操作，也可以让外部 AI 通过 MCP 直接操作同一个项目，完成建模、布景、角色调度、动作编排、运镜和视频导出。

产品的核心产物是具有明确空间关系、人物动作、构图和时间节奏的 3D 参考视频，用于后续 AI 短剧或短视频生成。

产品工作流到白模视频导出为止。用户自行决定如何使用该视频；产品不接入下游 AI 视频生成服务，也不规划控制图、模型适配或素材交接流水线。MCP 用于让外部 AI 操作本软件。

从导演视角，产品需要帮助判断：观众此刻应该看到什么、人物为什么行动、何时出现反应、在哪里切镜，以及不同镜头能否组成一场表达清楚的戏。白模预演应支持这些决定的比较和修改。

### 用户已明确的需求

- 产品形态为 Web 项目，提供实际可用的 3D 编辑能力。
- 主要制作白模，用于表达场景、人物、动作和镜头。
- 支持 MCP，允许 AI 直接调用软件进行建模和操作。
- 支持多种摄影机镜头及运动方式。
- 可以导出白模视频，作为 AI 短剧生成的参考。
- 功能设计参考成熟 3D 软件，本轮先梳理产品需求。
- 只需生成白模视频，不需要接入 AI 视频生产流程。
- 业务数据使用 SQLite 存储。
- 代码遵循统一规范和模块化设计，每个源码文件不超过 1000 行；这些约束属于项目目标的完成标准。

### 本稿的产品判断

- 优先服务短剧导演、分镜师、AI 视频创作者，以及替他们操作工具的 AI Agent。
- 首版围绕“可编辑的白模预演视频”形成完整闭环，逐步增加建模深度。
- 人工界面和 MCP 应共享项目状态、编辑命令及校验规则。
- “MCP 支持”是核心产品能力，需要与编辑器同时设计。
- 核心交付物为白模视频；项目保存与预览截图服务于编辑、检查和复用。
- 基础对白节奏、人物注视、镜头叙事意图和剪辑连续性纳入首版；这些能力优先于增加复杂建模工具。

## 2. 核心用户流程

镜头描述或剧本 → 拆分场次与剧情节拍 → 明确表演及镜头意图 → 场景搭建 → 角色调度与临时对白 → 拍摄覆盖镜头 → 剪辑预演与修改 → 导出白模视频。

支持三种使用方式：

| 方式     | 用户如何使用                                                   |
| -------- | -------------------------------------------------------------- |
| 人工操作 | 在浏览器编辑场景、动作和镜头，预览并导出                       |
| AI 操作  | 外部 Agent 理解用户意图，通过 MCP 查询、编辑、预览、修正和导出 |
| 混合操作 | AI 搭建初稿，用户接手调整；AI 再读取最新状态继续工作           |

自然语言示例：

> 创建一个客厅，放置沙发、茶几和门。两名角色分别站在门口和沙发旁。角色 A 走向角色 B。先拍双人全景，再切角色 A 的近景，最后从角色 A 肩后拍角色 B，并缓慢推进。导出 10 秒竖屏白模视频。

这条需求对应一组真实的场景、动画和摄影机编辑操作。用户可以逐项查看和修改结果。

## 3. 项目结构与连续性

| 对象           | 职责                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 项目           | 首版保存一个场次与场景、素材引用、镜头编排、导出设置与版本                           |
| 剧情场次与节拍 | 记录发生地点、时间、人物目标、信息揭示、对白及反应点，关联使用的 3D 场景             |
| 场景           | 保存空间、物体、角色和灯光；首版每个项目一个场景，多场次布景复用后续扩展             |
| 角色与道具     | 具备稳定 ID、名称、尺寸、变换、层级及可用动作等属性                                  |
| 表演           | 保存角色与道具的初始状态，以及动作、注视、对白和事件的源时间线；首版由项目内镜头共享 |
| 摄影机         | 保存位置、朝向、投影、焦距和相机动画                                                 |
| 镜头           | 引用当前场景、共享表演、摄影机及可用源时间区间，记录主体、叙事意图和拍摄设置         |
| 剪辑片段       | 引用镜头的源时间入出点，定义在成片中的位置和时长；首版默认原速                       |
| 镜头序列       | 编排剪辑片段和独立音轨，形成可连续预览和导出的视频                                   |
| 导出任务       | 记录项目版本、输出参数、进度、状态及产物                                             |

同一段表演可以从不同摄影机拍摄，形成全景、正反打、反应和道具特写等覆盖镜头。首版镜头共享项目内同一套表演，切镜不应意外重置角色、道具或空间布局。

表演源时间与成片时间分离：例如同一个开门动作，可以先用全景的前半段，再接手部特写的后半段；也可以有意重复少量动作或省略等待。连续性检查应提示可能的跳变，允许导演保留有意设计的剪辑。

成片音轨可引用表演源音频。默认保持对白、事件标记与动作的时间对应，连续源时间上的机位切换不重启音频。裁切、重复或省略源时间时，需要同步显示声音与动作的映射变化；可以显式解除同步并独立编排声音，同时标记该状态。

首版修改布景或表演会影响项目内所有使用相应源时间的镜头。镜头方案副本包含独立的摄影机参数、摄影机动画及剪辑参数，继续共享项目内布景和表演；修改新方案机位不改变旧方案机位。需要独立表演时通过项目 JSON 创建另一个项目保存，项目内部的命名表演版本及影响范围提示后续扩展。

## 4. 功能需求

### 4.1 场景搭建与建模

- 基础几何体：立方体、球体、圆柱、平面等，支持尺寸和比例参数。
- 物体操作：选择、多选、移动、旋转、缩放、复制、删除、显示、隐藏和锁定。
- 场景组织：命名、分组、父子层级、场景树、聚焦选中物体。
- 精确布局：数值输入、统一单位、网格吸附、对齐及落地摆放。
- 常用组件：墙、地板、门窗，以及桌椅、沙发等基础场景道具。
- 模型导入：首版建议支持 GLB/glTF，保留可用层级、骨架和动画。
- 白模显示：统一白色或中性灰材质，保留轮廓、遮挡关系、阴影和空间层次。
- 编辑辅助：坐标轴、网格、变换手柄及辅助线，可以在最终视频中关闭。

建模深度分阶段：

| 阶段       | 能力                                           |
| ---------- | ---------------------------------------------- |
| 首版建议   | 参数化几何体、现成组件组合、模型导入和对象变换 |
| 后续增强   | 挤出、布尔、曲线、吸附增强及可复用场景模板     |
| 进一步扩展 | 更深入的网格编辑、修改器或外部生成式 3D 服务   |

“AI 建模”在首版中的可验收含义是：AI 调用这些工具创建和编辑真实的 3D 场景。任意文本直接生成复杂人物或精细模型属于额外能力。

### 4.2 角色、动作与走位

- 提供至少一种带骨架的人形白模，支持身高调整和角色命名。
- 支持多个角色同场，角色身份在多个镜头间保持一致。
- 首版预设动作建议覆盖站立、行走和转身；坐下、起身、手势及更多表演动作逐步增加。
- 支持位置、朝向和动作片段的时间编排，可设置动作起止与播放速度。
- 支持角色按路径移动，协调位移与行走动作，避免明显滑步。
- 支持基础姿态调整和保持、头部朝向及注视目标，能够安排“看对方、低头、移开视线、停顿后抬头”等简单表演。
- 支持基础道具附着与持有状态，例如手机在 B 的右手中；首版允许手工调整接触姿态，复杂抓握、交接及手脚 IK 后续增加。
- 支持以对白、停顿和反应标记定位动作。首版标记与动作关键帧分别调整，修改对白或标记时长不会自动移动动作；关联重排后续扩展。
- 导入的任意模型不保证可以直接套用动作；需要明确提示骨架和动画的兼容情况。

角色移动、骨骼动作和摄影机运动是独立可编辑的轨道。首版不承诺自动完成复杂打斗、面部表演、口型或物理接触解算。

### 4.3 摄影机与镜头语言

- 区分编辑器观察视角与实际拍摄摄影机，避免操作视口时误改镜头。
- 支持多摄影机，明确每个镜头使用的摄影机。
- 支持位置、朝向、焦距或视场角、画幅比例等基础设置。
- 常用构图预设：远景、全景、中景、近景、特写、双人镜头和过肩镜头。
- 常用机位：平视、俯视、仰视及高位俯拍。
- 运镜能力：固定、推拉、摇镜、横移、升降、跟随、环绕和路径运动。
- 基于目标与包围范围计算构图，允许用户和 AI 继续精调。
- 支持摄影机位置、朝向、目标和焦距关键帧，以及基础缓入缓出。
- 提供画幅边界、构图参考线和拍摄画面预览。
- 每个镜头可指定叙事主体和摄影机朝向目标，预期可见对象与焦点意图记录在镜头备注中；首版不提供独立光学对焦参数。
- 首版显示基于视场角换算的 35 mm 等效焦距；独立光学对焦、可见景深和移焦后续增加。
- 提供固定构图线和安全区参考，辅助检查头顶空间及视线留白。首版画幅是项目级设置；可配置平台遮挡区及横竖屏独立构图后续扩展。

景别、机位、焦距和运动方式可组合。预设负责生成可编辑的摄影机参数。

### 4.4 时间线与镜头编排

- 支持播放、暂停、拖动时间游标、逐帧查看和循环预览。
- 展示角色、物体、动作及摄影机轨道。
- 支持增加、移动、修改和删除关键帧。
- 支持设置镜头起止时间、时长、排序及切镜点。
- 支持单镜头预览与完整镜头序列预览。
- 支持表演源时间和成片时间的对应查看，剪辑片段可裁切、重排，并复用同一段表演的不同机位。
- 首版支持导入临时对白音轨、设置播放位置、音量和静音，并添加台词、停顿、反应及关键音效标记。
- 音轨独立于画面切镜，连续对白不会因更换机位重启；允许对白期间切到听者反应。
- 时间线显示节拍、动作关键帧及镜头源时间范围，可检查成片中的停顿长度。音轨显式选择源时间或成片时间基准，前者随剪辑映射，后者独立编排；首版不自动将对白标记与动作关键帧绑定。
- 首版以硬切和原速剪辑为主；高级音频编辑、转场、复杂变速、自动配音和口型同步作为后续增强。

### 4.5 白模视频导出

- 首版输出可播放的 MP4，支持当前镜头和完整镜头序列。
- 支持横屏 16:9 和竖屏 9:16，设置帧率、分辨率和输出范围。
- 首版验收建议采用 720p、24 fps；1080p、其他帧率及更高分辨率按性能验证扩展。
- 导出内容来自指定摄影机，不包含编辑器网格、选框和操作手柄。
- 逐帧按时间线采样，确保视频时长和动作速度不随机器实时预览帧率改变。
- 提供进度、取消、错误说明、重新导出和产物下载。
- 导出绑定明确的项目版本或快照，导出过程中继续编辑不影响该任务内容。
- 支持保存可重新打开的项目文件；指定帧截图用于人工审查和 MCP 预览反馈。
- 支持包含临时对白的审片视频，以及可选择静音的干净参考视频。
- 支持分别导出选定镜头的白模视频，或按镜头序列输出完整视频。
- 审片版可叠加镜号和时间码，干净参考版不叠加标注。

导出完成后提供视频下载。对白、镜头意图和角色 ID 等编辑信息保存在项目内，无需额外生成面向下游模型的素材包。

### 4.6 导演拆戏、调度与审片

#### 叙事与表演意图

- 首版允许手工或通过 MCP 建立场次、剧情节拍和对白记录；完整剧本自动解析后续增加。
- 每个节拍记录人物目标、可见动作、观众应获得的信息，以及需要延迟揭示的信息，并关联对应镜头。
- 镜头可标注建立空间、交代动作、人物反应、主观视角、信息揭示或细节插入等用途。
- 支持记录表演备注和情绪变化，并落到可预演的停顿、姿势、距离、视线和动作速度上。
- 白模不能充分表达微表情、眼神细节或复杂面部表演；首版通过姿态、视线和节奏预演，补充意图保存在项目的镜头备注中。

#### 俯视调度与连续性辅助

- 提供可直接调整人物、路径和摄影机的俯视调度图，显示视锥及选定时刻的位置。
- 支持标记人物交流轴线、运动方向和注视关系，对比相邻镜头中的画面左右关系。
- 对越轴、视线衔接、入画出画方向、动作阶段和道具持有状态提供人工检查入口；自动检查仅覆盖已定义、可计算的规则，并标注时间点和依据。
- 轴线可随调度改变；不明确时允许导演手动标定。越轴、跳切和省略动作均为提示，不阻止播放或导出。
- 支持比较切点前后帧，检查人物位置、朝向、手势、持物、门开关等状态。
- 摄影机穿墙、主体被遮挡或出画应可检查；有意遮挡、空镜和揭示镜头可以保留。

#### 画面可读性

- 首版提供可调方向、强度的基础灯光及环境光，帮助判断人物轮廓、阴影、前后层次和道具可见性。
- 保留白模输出，同时提供编辑用角色标识或中性灰度差异；标识是否进入导出由输出模式决定。
- 焦点、光线和遮挡需要服务镜头的信息顺序，例如先看见 B 的反应，再看见其手中的手机。
- 后续扩展布光方案、可见景深和移焦预演，优先表达视觉注意力及揭示时机。

#### 覆盖镜头与改稿

- 提供带缩略图的镜头清单，按剧情节拍查看全景、正反打、反应镜头和道具特写是否已准备；覆盖项由导演选择。
- 首版支持保存、复制和恢复镜头序列方案，比较不同切点和时长；并排同步播放及团队审片作为后续增强。
- 支持按镜头和时间点记录修改意见，首版可作为本地项目备注。
- 可锁定已确定的角色走位、对白、镜头或时长。AI 改稿需读取并遵守锁定范围，约束冲突时返回具体原因。
- 例如“只让最后一镜更有压迫感”应限定为该镜头的候选调整，预览后可恢复，不得静默改变整场表演。

导演视角的首版优先级：

| 优先级           | 能力                                                         | 判断依据                                 |
| ---------------- | ------------------------------------------------------------ | ---------------------------------------- |
| P0：首个可用版本 | 节拍和镜头意图、临时对白、停顿反应、注视、基础持物           | 能否预演一场有信息变化和表演节奏的对白戏 |
| P0：首个可用版本 | 源时间与剪辑时间分离、覆盖镜头、俯视调度、切点前后帧检查     | 能否判断镜头是否接得上、戏是否看得懂     |
| P0：首个可用版本 | 基础灯光、安全区、方案副本、范围锁定、白模视频导出           | 能否检查、修改并导出可用视频             |
| P1：效率增强     | 自动连续性提示、可见景深与移焦、IK、丰富动作库、同步方案对比 | 减少人工检查和调姿成本                   |
| P2：进一步扩展   | 精细表情、复杂接触、专业剪辑和完整自动剧本拆解               | 在基础导演工作流成立后提高表达深度       |

## 5. MCP 与 AI 操作需求

AI 必须具备“发现能力 → 读取现状 → 编辑 → 查看结果 → 修正 → 导出”的闭环。

以下工具名仅用于表达能力边界，实际接口在技术设计阶段确定：

| 能力           | 示例工具                                                  | 必要反馈                                                   |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------------- |
| 能力发现       | `capabilities.list`                                       | 对象类型、动作、运镜和导出规格                             |
| 项目与场景查询 | `project.get`、`scene.inspect`                            | 稳定 ID、当前版本、层级、单位、坐标系和时间线              |
| 导演意图       | `beat.update`、`shot.intent.set`、`annotation.add`        | 节拍、对白标记、镜头用途、关联对象及修改意见               |
| 建模与布景     | `object.create`、`object.update`、`asset.import`          | 创建或修改结果、对象 ID、实际参数                          |
| 角色与动作     | `actor.add`、`animation.set`、`path.set`                  | 角色、动作范围、资源兼容性及失败原因                       |
| 镜头设计与剪辑 | `camera.set`、`shot.create`、`sequence.update`            | 摄影机参数、表演版本、源时间入出点和成片位置               |
| 结果检查       | `preview.capture`、`scene.validate`、`continuity.inspect` | 指定帧与切点前后图片、轴线和对象状态；自动判断注明能力范围 |
| 修改范围       | `edit.scope.set`、`sequence.duplicate`                    | 锁定对象、可改参数、候选版本及受影响镜头                   |
| 修改恢复       | `history.undo`、`project.save`                            | 恢复结果、保存版本                                         |
| 视频导出       | `render.start`、`render.status`、`render.cancel`          | 任务 ID、进度、错误及可访问的产物地址                      |

必须覆盖的交互约束：

- UI 和 MCP 对同一项目的修改可以相互看到，人工能够接手 AI 的结果。
- 参数使用明确单位和坐标约定，对象引用使用稳定 ID。
- 支持一组相关编辑形成可撤销操作；批量执行应明确失败回滚或部分成功语义。
- 使用请求标识或等效机制避免网络重试造成重复物体和重复导出任务。
- 人工与 AI 并发编辑时校验版本，冲突需返回最新状态并明确处理结果。
- 支持指定镜头、摄影机和时间点截图，让具备视觉能力的 Agent 检查构图。
- 耗时导出采用异步任务，AI 可以查询、取消并获取产物。
- 远程 MCP 访问需要项目授权；远程客户端获取素材不能依赖仅服务器可见的本地路径。
- MCP 会话或浏览器断开后，已保存项目和服务端导出任务的状态应可恢复查询。
- AI 可以读取导演意图、对白和反应标记、物体状态、镜头覆盖关系及锁定范围；这些信息与几何参数同样属于项目状态。
- “更紧张”“犹豫后再回答”等指令由 Agent 转换为明确的表演和镜头编辑，并说明采用的表达方式；工具层负责执行、约束校验和预览反馈。

MCP 是接入协议。外部 AI 的自然语言理解、任务规划和视觉判断由所接入的 Agent 提供；内置聊天助手是可单独增加的产品入口。

## 6. 编辑器工作区

借鉴成熟 3D 软件的场景树、视口、属性面板和时间线习惯，围绕短剧预演组织工作区：

- 中央：3D 编辑视口，可切换至拍摄摄影机画面。
- 调度视图：俯视人物路径、交流轴线和摄影机，支持与拍摄画面对照。
- 左侧：场景层级及角色、道具和模型资产。
- 右侧：选中对象、动作和摄影机属性。
- 底部：镜头缩略图、表演及剪辑时间线、对白和反应标记、轨道及播放控制。
- 导演面板：当前场次和节拍、镜头意图、锁定项及带时间点的修改意见。
- 顶部：项目、编辑工具、保存、撤销重做和导出。
- AI 状态区域：连接状态、当前操作和任务结果；聊天入口按后续范围决定。

首版主工作环境建议为桌面浏览器，支持鼠标和键盘。移动端优先满足预览和查看导出产物，复杂编辑能力另行规划。

## 7. 首版建议范围与验收

首版必须包含：可操作的 Web 编辑器、基础建模与资产组合、骨架白模及基础表演、导演节拍与临时对白、可编辑摄影机动画、表演和剪辑时间线、基础连续性检查视图、完整 MCP 操作闭环、项目保存恢复及白模视频导出。

端到端验收场景是一场 10 秒双人对白戏：A 进入客厅质问 B；B 先看手机，在台词结束后停顿半秒，再抬头看 A；末镜揭示 B 手中的手机。

1. 外部 AI 仅通过 MCP 新建项目，搭建包含地板、墙、门、沙发和茶几的室内场景。
2. 记录“质问、停顿反应、手机揭示”三个剧情节拍及观众应获得的信息，导入一段临时对白并标记台词结束点。
3. 创建两名白模角色，编排 A 走近、B 持手机低头、在台词结束 12 帧后开始抬头看 A 的动作；以 24 fps 验证半秒停顿。
4. 准备双人全景、B 的反应近景、手机特写三个覆盖镜头，至少一镜包含连续运镜；对白可以跨切镜连续播放。
5. 使用同一表演版本的不同机位完成 10 秒剪辑。显示每段源时间与成片位置，可裁切并检查切点前后帧，人物朝向、视线和手机持有状态符合安排；源时间和最终成片中的台词结束至抬头间隔均为 12 帧。
6. 在俯视调度图和拍摄画面中检查轴线、角色左右关系和揭示时机；B 在反应镜头中可见，手机在计划的揭示镜头前不意外暴露。
7. 保存两个剪辑方案；锁定人物动作和对白后，让 AI 仅调整最后一镜。人工修改该机位后，MCP 能查询新参数，先前方案仍可恢复。
8. 导出 10 秒、720 × 1280、24 fps 的竖屏 MP4，共 240 帧；带对白审片版音画时间对应，干净参考版无编辑辅助和审片标注。
9. 单独导出其中一个镜头的白模视频，画面和时长与该镜头的选定范围一致。
10. 保存并重新打开项目，节拍、角色、动作、对白、道具状态、镜头序列和锁定设置保持一致。
11. 对重复请求、无效对象引用和导出失败给出明确反馈；一次相关编辑可撤销并恢复。连续性提示允许被导演保留，不强制改镜头。

首版不纳入完整雕刻、复杂拓扑编辑、专业材质节点、布料毛发、流体、复杂动力学和高级面部动画。完整产品可按真实创作需求逐步增加能力。

## 8. 后续优先级建议

| 阶段     | 目标                       | 代表能力                                                            |
| -------- | -------------------------- | ------------------------------------------------------------------- |
| 第一阶段 | 完成导演预演与视频导出闭环 | 白模场景、基础表演、节拍对白、镜头剪辑、调度检查、MCP、白模视频导出 |
| 第二阶段 | 提升短剧预演效率           | 场景模板、动作库、IK、自动连续性提示、可见景深与移焦、方案对比      |
| 第三阶段 | 扩展建模与表演能力         | 更深的几何编辑、姿态与动作工具、可复用资产管理                      |
| 第四阶段 | 提升规模与协作能力         | 大场景与长视频性能、版本比较、团队协作                              |

技术方案阶段需要验证浏览器渲染与视频编码路径、骨架及动作资源来源、长任务执行方式和 MCP 部署方式；这些选择不改变上述产品闭环。

## 9. 工程完成标准

- SQLite 持久保存项目、历史记录、幂等请求、资产元数据及导出任务。二进制模型、音频和视频文件由数据库引用。
- 领域模型、场景渲染、Web 界面、持久化、HTTP/MCP 协议及视频编码按职责拆分；Web 与 MCP 共用编辑命令。
- 每个源码文件不超过 1000 行，构建过程自动检查。不能通过压缩代码排版规避限制。
- TypeScript 严格类型检查与未使用变量检查通过，Prettier 统一格式，外部输入在边界校验。
- 领域测试、SQLite 与 MCP 集成测试、浏览器端到端测试通过；真实视频必须经过 FFprobe 检查。
- 桌面与手机预览进行截图和 canvas 像素检查，确认场景非空、动画实际变化、无文本溢出。
- 本地服务实际启动，提供可用编辑器地址、MCP 配置入口和运行文档。
