## 制作暴露的通用修复

- 车辆间距与布景错误通过公开 MCP 修改独立路径和相机关键帧解决，未增加电影专用渲染逻辑。
- 移动端路径编辑框改用 Portal，390 像素视口下实际浏览器测试通过并已查看截图。
- 重复时间关键帧被领域校验原子拒绝，制作脚本合并已有关键帧；服务层由根代理补齐 `VALIDATION_ERROR` 分类与 HTTP/MCP 回归。
- 旅游拱门连续布尔采用库内约束三角裁剪，闭合检测先归一化坐标；不同尺寸连续减法/并集与删面拒绝回归通过。

## 太空正式成片复核

2026-09-07，正式项目 `f6fea4fb-95eb-48ae-b8eb-60d2b1129c68` 的 r90 视频触发冻结告警。实际解码图像非黑帧，前六秒逐帧 MD5 不同；问题来自多个跟随机位过宽、主体屏幕运动过弱。通过公开 MCP 调整八台摄影机，按所选动作的空间包围范围取景，并增加 37–43 度独立摄影机弧线。两个爆炸镜头将 18 米效果边界计入取景。改稿脚本为 `scripts/production/space-cinematography.ts`，所有机位仍是可编辑关键帧。

新的正式视频绑定项目 r106，任务 `b4cd9819-778b-475c-84cc-277fc6c6831d`。产物 `.data/full-delivery/productions/space/space.mp4`，SHA256 为 `b04723f299969f9d5129b1301c3a8ca0867831b089675c2331b2e71d74f0d650`。ffprobe 确认为 H.264、1280×720、24 fps、2880 帧、120 秒及 AAC 音轨；文件 6,040,305 字节。

`review-film.ts` 完整解码全部 2880 帧，原有检测阈值未变：零黑帧区间、零超过一秒的冻结区间。应用内从头播放至 120 秒结束，2 倍速审片记录最后计数为 2886 次显示/解码累计、93 次浏览器丢帧；离线视频本身的 2880 帧均成功解码，不能把浏览器播放统计当作视频缺帧。桌面与 390 像素手机播放器截图实际检查，无横向溢出或页面错误。

实际检查四张分时段联系表的 60 个视频帧、八张应用内播放截图及手机截图，覆盖编队、追兵、齐射、规避、两次爆炸和结束航向。36–48 秒及72–84秒的追踪镜头保留飞行器滚转与碎星视差，60–72 秒和96–108秒可见命中占位及分散碎片；没有发现抽样帧中的黑画面、缺失主体或错误镜头顺序。最后一张联系表末行的黑格是 `tile` 对不足16个图像的空位填充，视频解码无黑帧。几何代理检查重新覆盖2880帧，静止区间、载具OBB相交和全体载具中心出画均为零。
